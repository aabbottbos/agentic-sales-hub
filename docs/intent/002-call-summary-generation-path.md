# 002 — call-summary generation path

**Tier:** tier:2
**Status:** draft
**Issue:** #7

## Problem

Phase 0 proved the deterministic skill path (`find-evidence`, `sow-review`) —
where `sow-review`'s `blocker_recall = 1.00` gate is a property of code. Nothing
yet proves the **LLM-backed generation path**: a skill that reads context and
writes prose. Before committing to three generation skills, the MCP server, and
trace emission all at once (issue #7's full scope), one generation skill needs to
be proven end-to-end — does the `SkillImpl` seam actually hold an LLM impl with
no change to the skill-def schema or the eval harness, and can generated output
be scored against a golden set the way retrieval and review already are?
`call-summary` is the lowest-liability, most-checkable choice: a meeting note in,
a structured summary out, where commitments and next steps are objectively
present or not.

## Proposed outcome

`call-summary` exists as an LLM-backed impl in
`packages/skills/src/impl/call-summary.ts`, behind the existing `SkillImpl`
interface — no change to the skill-def schema, `runSkill`, or the eval harness
shape. It takes a path to a corpus meeting note and returns a structured object —
`{ summary, commitments[], next_steps[], context_deltas[], citations[] }` —
validated against a new `context/schema/summary-output.json` output-contract
schema. It does **not** persist an artifact (no `writeArtifact`), build the MCP
server, or touch `call-prep` / `proposal-draft`.

A new **generation** eval class exists: an LLM-judge rubric (grounding /
completeness / tone / structure, ≥ 4.0/5) plus deterministic citation-validity
(= 1.00) and commitment-recall (≥ 0.90), with the judge prompt, model ID, and
rubric versioned in the repo.

## Who it affects

- **`packages/skills`** — new `call-summary` YAML definition + `impl/call-summary.ts`,
  the first LLM-backed impl; `runSkill` output-contract enforcement now exercises
  a generation output.
- **`context/schema/`** — new `summary-output.json` output-contract schema
  (schema change → tier:2 on its own).
- **`evals/`** — new generation scorers (rubric + commitment-recall), a judge
  harness, generation-class cases, and a new eval gate (eval-gate change → tier:2).
- **`.claude/skills/call-summary/SKILL.md`** — generated by `skills:sync`.
- **CI** — `evals.yml` gains a step that makes a live model call.
- **Not touched:** `packages/context-core` (no `writeArtifact` this slice),
  `context/accounts/**` (no persistence), the MCP server, `apps/surface/`.

## Constraints

1. **Tier:2, full chain.** Schema + skill contract + eval gate all change. Intent
   → spec → plan all committed before code.
2. **Provenance (invariant #4).** Every material claim in the summary needs a
   resolvable citation; anything unsourced is marked `[unsourced]`, never
   asserted. Applies to generation output from day one (amendment §14).
3. **Grants at the loader (invariant #6).** `call-summary`'s read grant is
   declared in its YAML def and enforced by `resolveScope`, not prompt. Input is
   one meeting note under `context/accounts/.../meetings/` — accumulating
   context, not `inbound/**`, not untrusted.
4. **No persistence this slice.** `call-summary` returns a structured object
   only. No `writeArtifact`, no `outcomes.jsonl` entry — deferred to WI-2.
5. **No net regression.** The Phase 0 gates stay green — `sow-review` (blocker
   recall 1.00, precision ≥ 0.70, citation validity 1.00), `find-evidence`
   (recall ≥ 0.90, citation validity 1.00), `injection: PASS`.
6. **The `SkillImpl` seam must not change.** If it needs a schema or interface
   change to hold an LLM impl, that is a finding, not a workaround.
7. **Determinism where it counts.** Citation-validity and commitment-recall stay
   rule-based; only the rubric is LLM-judged.

## Open questions

1. **Confirm `@anthropic-ai/sdk` direct** (not the Claude Agent SDK), with the
   LLM call kept behind a single seam/function rather than scattered call sites.
   Model-portability across foundation-model vendors is an **explicit non-goal
   for v1** — the eval gates (grounding rubric, citation validity) are calibrated
   against one model and one judge model, and a user-swappable model invalidates
   the golden-set scores that are half the credibility story. Revisit as a fast
   follow only if there is real demand; keep the seam narrow so that stays
   possible.
2. **CI auth + gating of the flaky judge run.** `ANTHROPIC_API_KEY` vs. a Claude
   Code OAuth token (largely follows from OQ1); retry policy; hard-fail vs.
   skip-with-warning; on the `evals.yml` critical path or a separate job.
3. **Concrete shape of `context_deltas[]`.** A labeled free-text list, or a
   defined structured shape a later step (a future context-update / `writeArtifact`
   path) could apply mechanically.
4. **Golden-set sufficiency.** Whether the 3 existing Acme meeting notes are
   enough, or 1–2 new Acme notes are needed. **Scope fence:** the spec may add at
   most 1–2 new Acme meeting notes; anything beyond that (a second opportunity,
   the §10 corpus expansion) kicks back to a separate intent (WI-4).

## How we'll know it worked

1. **(load-bearing) `call-summary` runs end-to-end** against a corpus meeting
   note in Claude Code via `runSkill`, returning an object that validates against
   `context/schema/summary-output.json` — with **no change** to
   `skill-def.schema.json`, `runSkill`'s signature, or the eval harness
   interfaces. If any of those had to change, the seam claim failed.
2. **Generation eval gates pass** on the golden set: LLM-judge rubric ≥ 4.0/5
   aggregate; citation validity = 1.00 (deterministic); commitment-recall ≥ 0.90
   (deterministic) on labeled commitments.
3. **No net regression** — `sow-review` and `find-evidence` gates stay green;
   `injection: PASS` holds.
4. **Provenance holds** — in a manual read of the generated summaries for the
   golden cases, every material claim carries a resolvable citation or an
   explicit `[unsourced]` marker; zero unmarked unsourced assertions.
5. **The judge is reproducible** — judge prompt, model ID, and rubric are
   committed; a second run of `pnpm eval --suite call-summary` produces a rubric
   score within a documented tolerance band (the spec sets the band and the
   retry policy).
6. **A committed eval result** for the `call-summary` suite lands in
   `evals/results/`, and `evals.yml` runs the suite on PRs touching the relevant
   paths.
